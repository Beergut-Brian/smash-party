# Smash Party — guide for AI collaborators

A co-op driving-and-smashing game for a dad and his 5-year-old, played on a TV with two controllers. Plain HTML + three.js (r186 via an import map; `src/boot.mjs` exposes it as the global `THREE`), no build step, no frameworks. GitHub Pages serves `main` as-is.

## Agent roles
Every session has a role. Started with "You are the `<role>` agent", read `agents/<role>.md` and follow it: it says what you own, what to work on and how to finish. Index: `agents/README.md` (logic, audio, cars-ui, world-props, world-animals, world-bosses, zone-<name>, qa, reviewer, art-pipeline).

## Design rules (do not break these)
- **Co-op only.** No losing, no timers that end the game, no player-vs-player scoring. Everything feeds one shared smash meter.
- **Kid-simple controls.** Stick = point where you want to go. A/RT = turbo, B = jump (becomes 💥 BOOM when stuck), X or Y = shoot (and LEVEL UP when the gold button shows; either works because 8BitDo/Nintendo pads swap the X/Y labels; LB/RB also LEVEL UP). Cars change only in the level-up garage: drive into the car you want. Never require reading.
- **Big, loud, funny feedback.** Every action should have a sound, a puff, or a wobble.
- **Original designs only.** No real car brands, toy lines, logos, or licensed characters.
- Must run smoothly at 1080p on a GTX 1060. Computer only (TV via PC + controllers); phone/touch support isn't needed, so don't spend time on it.

## Layout & who owns what
Several lanes work on this repo at the same time: **logic** (Claude Code), **cars & UI** (Cursor), and three **world** lanes run as separate Claude Code design sessions: **world-props**, **world-animals** and **world-bosses**. Stay in your lane to avoid merge conflicts.

| File | Owner | What's in it |
|---|---|---|
| `src/cars.js` | **Cursor** (cars & UI) | Block-built car models + the `CARS` list, model-car loader |
| `src/objects.js` | **world-props** session | Smashable objects (`OBJ`), buildings, mega set pieces, zone layouts (`ZONE_LAYOUT`, `ZONE_PROPS`), arena (`buildWorld`), respawn mix (`SPAWN_W`). Its builder helper is `sized(x,z,r,h,points,size,build,extra)` |
| `src/world/animals.js` | **world-animals** session | `ANIMAL` looks |
| `src/world/bosses.js` | **world-bosses** session | `BOSSES` models |
| `src/world/zones/<name>.js` | **zone-<name>** session | One themed zone each (plug-in contract: L15 ✅) |
| `style.css` | **Cursor** (cars & UI) | All UI styles |
| `assets/**` | **Cursor**: `assets/cars/`, UI art. **world-props**: `assets/props/` (top level), `assets/textures/`. **world-animals**: `assets/props/animals/`. **world-bosses**: `assets/props/bosses/` | `.glb` models, `cars.json`, textures, sounds (except the generated `assets/sounds/voice/`, `sfx/` and `music/`) |
| `tools/`, `assets/sounds/voice/`, `sfx/`, `music/` | **Claude Code** (logic; the **audio** role runs the generators) | ElevenLabs generators (`make-voices.mjs`, `make-sfx.mjs`, `make-music.mjs`), their lists (`*-lines.json`), and the generated mp3s + `index.json` |
| `src/core.js` | **Claude Code** (logic) | Helpers (`mk`, `M`, `E`, `rand`…), renderer, scene, ground/roads/walls, ramps + `groundH`, audio |
| `src/game.js` | **Claude Code** (logic) | Debris, smashing, scoring, respawn, celebration, players/driving, input, collisions, camera, HUD, main loop |
| `src/boot.mjs` | **Claude Code** (logic) | Imports three.js + addons, sets `window.THREE`, loads the plain scripts in order |
| `index.html`, `CLAUDE.md` | Shared | Change rarely; mention it in the commit message |

Scripts are plain (no modules); `src/boot.mjs` loads them in order: `core.js` → `cars.js` → `objects.js` → `world/animals.js` → `world/bosses.js` → `game.js`. Materials: use `M(color)` / `mk()` (toy-plastic `MeshStandardMaterial` on high, Lambert on FAST) or `litMat({...})` for custom ones, so the quality toggle covers them. **Prefer `M(color)`:** sleeping props, scatter and debris are batched by shape with the color per instance, so `M()` colors are nearly free to draw, while each custom material adds its own draw call per chunk. Top-level `const`/`function` names are shared across files, so never reuse a name.

If a design change needs new logic (or the other way around), make the part in your own file and leave a `// TODO(logic):` or `// TODO(design):` note for the other tool instead of editing their file.

## Parallel sessions (rules)
- Each session edits **only its own files and asset folder** (table above). Need something from another lane? Leave a `// TODO(<lane>):` note or add a task in `TASKS.md`.
- Work on a branch named after your lane and task (`world-props/D8b`, `world-animals/D3`, `cars/recipes`) and open a PR. Never push straight to `main` from a design lane.
- **Use your own `git worktree`, never switch branches in the main folder.** Several sessions share this folder; a `git checkout` there silently moves everyone else onto your branch (it already landed a logic commit on the wrong branch once). Start a session with `git worktree add ../smash-party-<lane> -b <lane>/<task> origin/main` and work only in that folder; remove it with `git worktree remove` when merged. The main folder stays on `main`.
- **Don't bump `version.json` on a branch.** It's bumped once when the PR merges.
- `assets/props/props.json` is shared: **only add new keys** (no reordering or reformatting) so merges stay clean.
- In `TASKS.md`, only check off and edit your own task.
- Top-level names are global across all scripts: prefix new helpers in a world file with the lane (`animal…`, `boss…`) so two lanes never define the same name. (The GLB loader is `prop(name, fallback)` in core.js; don't define another `prop`.)

## Tasks
`AGENTS.md` must stay an exact copy of this file (Cursor reads it): after editing either, copy it over the other.

Check `TASKS.md` before starting. Take the top unchecked task in your section, check it off in the same commit as the work, and add follow-up tasks for the other tool when needed.

**Hand-off rule (placeholders):** whenever you add something another lane must finish, add a task for that lane in `TASKS.md` in the same commit, tagged `NEEDS DESIGN` or `NEEDS LOGIC`, saying what exists, where, and what's needed. Examples: logic adds a new animal kind, boss, prop type or UI element with a placeholder look, so it adds a `NEEDS DESIGN` task for the right lane (world-props, world-animals, world-bosses, or cars & UI). A design lane adds something that needs code (a new animal kind needs a sound and herd spot; a model needs batching), so it adds a `NEEDS LOGIC` task. A task with no owner lane is a bug in the hand-off.

## Git workflow
- **Version:** bump `version.json` with every push to `main` (patch `0.12.1` for fixes, minor `0.13.0` for features). The start screen and pause menu show it, and the loader in `index.html` loads the game files with `?v=<version>` so the TV picks up new code. If two pushes collide on it, keep the higher number and bump once more.
- **Pull before you start. Commit small. Push when done.** Never force-push `main`.
- `main` is live on the TV (GitHub Pages: https://beergut-brian.github.io/smash-party/), so only push working code. Use a branch for big experiments.
- Commit messages start with the area: `cars: add Comet Crusher`, `logic: bigger barrel explosions`.

## Coordinate conventions
- Y is up. Forward for any car/object is **+Z** at `rotation.y = 0`; heading θ points along `(sin θ, cos θ)`.
- The camera looks from +Z toward −Z, so screen-up is world −Z.
- The world spans ±440 (`ARENA`) as an 11×11 grid of 80×80 chunks (`CHUNK`); chunk (0,0) is centered on the origin. The original hand-built arena (`buildWorld`) fills the middle, ±72 (`HOME`). Roads run every 160 units. Units ≈ meters; a car is ~4–5 long.
- Only chunks near the players are built. Objects sleep in shared instanced pools (one draw call per shape for the whole world, undamaged pack buildings drawn from their `o.proxy`) and wake into real meshes only when something hits them. Animals draw instanced per kind and material; block-built cars are merged per material except the wheels. Smashed things are remembered per chunk and regrow after a couple of minutes.

## Adding things
- **Block-built car:** write `buildX()` returning `{g, wheels, ex, h}` (see `buildMonster`) and add it to `CARS` with `name, emoji, speed (20–32), r (collision radius ~2–2.8)`, plus `tier` (0 = starter cars at the tiniest sizes … 3 = the coolest cars at the biggest sizes; a new tier unlocks every 2 sizes) and optionally `weapon: 'bubble' | 'cannon' | 'rocket'` (default: tiers 0–1 bubble, tier 2 cannon, tier 3 rocket). Until `tier` is set, `CAR_TIER` in game.js decides. Optional stats (L18): `power` 1–5 (buildings 1 size bigger need 3+ to chip, 2 sizes bigger need 4+; 3+ sizes bigger always boing), `handling` 1–5 (turning + grip) and `perk: 'autoRockets' | 'magnet' | 'bulldozer' | 'bouncy'` (fires rockets at nearby stuff on its own / slurps up smaller stuff around it / same-size buildings fall in one hit and +1 power / jumps twice as high). Missing stats come from tier, size and speed (`carStats(c)` in game.js); balance faster = weaker. The garage cards show them as ⚡ 💪 🌀 dots plus weapon and perk icons (`.garageCard .perk`).
- **Model car (for graphics models/tools):** drop `name.glb` in `assets/cars/` and add to `cars.json`:
  `{"name":"Comet Crusher","emoji":"☄️","file":"comet.glb","speed":27,"r":2.3,"scale":1,"y":0,"rotateY":0,"height":3,"exhaust":[0,1,-2.5]}`
  Model faces +Z, about 4–5 units long, under ~20k triangles. Meshes named `*wheel*` spin.
- **Zone layout:** define `const ZONE_LAYOUT={town(ctx){…},farm(ctx){…},park(ctx){…},home(ctx){…}}` in `objects.js`. Each function fills one 80×80 chunk. `ctx` has `zone, ci, cj, x0, z0, x1, z1, cx, cz, size` plus `place(type,x,z,arg,r)`, `ramp(x,z,th,L,W,H)` and `free(x,z,r)`. `place` and `ramp` return false (and do nothing) if the spot is off the chunk, on a road, on a ramp or overlapping. `Math.random`/`rand`/`pick` are seeded while a layout runs, so the same chunk always comes out the same. Which zone each chunk is in lives in `ZONE_MAP` (`core.js`).
- **Spots (L19):** in a layout, `ctx.spot(kind,x,z,w,d,th)` marks a `w×d` area centered at x,z (turned `th` radians, like `rotation.y`) such as `'yard'`, `'sidewalk'`, `'road'`, `'field'`, `'sand'`, `'parking'`, `'porch'`, `'path'` (any name works). About 85% of the size-matched filler near the cars then lands inside spots, using that kind's props: `const SPOT_PROPS={yard:{mini:['gnome',…],tiny:[…],…},field:{…}}` in `objects.js` (a themed zone can override with `registerZone({spots:{yard:{tiny:[…]}}})`). A spot kind with no list for a size uses the zone's normal size list. Spots don't block `place()`. `__sp.spots()` shows the spots of built chunks as colored tiles (again to hide).
- **GLB prop (art pack models):** drop `name.glb` in `assets/props/` and list it in `assets/props/props.json`: `{"oak_tree":{"file":"oak_tree.glb","scale":1,"y":0,"rotateY":0}}` (model faces +Z, feet at y=0, under ~5k triangles). In a builder, use `prop('oak_tree', () => blockBuiltFallback())`: it returns a cheap copy of the model, or the fallback if the model isn't there. The world waits for listed models to load before it builds. A model used as one part (`P(prop('oak_tree'),5)`) shatters into chunks colored like its first material.
- **Rolling / spinning:** pass `{roll:true}` in `makeObj` opts for things that should tumble away when hit (hay bales) instead of shattering. Set `mesh.userData.spin = {axis:'z', speed:1.2}` on a part to spin it in place (spinning objects stay awake, so use it for a few landmarks, not scatter).
- **Level-up garage (L17):** every new car tier (sizes tiny, medium, huge) opens a garage: up to 4 parked cars per player from the new tier on pads in the player's color, each with a stat card (icons + dots). Drive into one to pick it; when everyone has picked, GO! (A / START) rolls a fresh world at the same size. Cars only come from `CARS` by `tier`. Cars still missing are listed in `GARAGE_WANTED` (game.js) and show up as blocky placeholders with a ❓ card until a car with the same name exists in cars.js / cars.json. Optional look: `function buildGarage(){…}` in cars.js returns a `THREE.Group` (round floor about 26 units in radius at car scale 1, floor top at y=0, open toward +Z where the camera is; logic scales and places it); style `.garageCard` (`.soon` = placeholder, `--pc` = player color) and `#garageGo` in style.css.
- **Start spot:** both players start on the street at `SPAWN_DEFAULT` in game.js (right lane of the road at x=0, z≈48, facing −Z), and NEW WORLD puts them back there. To move it, define `const START_STREET=[[x,z],[x,z]]` in `objects.js` (P1, P2) and dress the spot for micro-sized cars (curb, sidewalk, mailbox, toy-sized clutter). The camera keeps each car about the same size on screen at every size, so the world around the start is what makes the cars feel tiny.
- **Launch pad look:** define `function buildLaunchPad(){…}` in `objects.js` returning a `THREE.Group` about 2.15 units in radius with its top near y≈0.3 (logic scales and places it, and bobs any child with `userData.arrow`). Without it, logic's rainbow pad is used.
- **Themed zone (plug-in):** copy `src/world/zones/_example.js` to `src/world/zones/<name>.js` and add `"<name>"` to `src/world/zones/index.json` (boot.mjs loads every listed zone after the world files, before game.js). The file calls `registerZone({id, letter, ground, sky:{top,horizon}, weight, props:{<name>_thing:(x,z)=>sized(…)}, sizes:{micro:[…],…,mega:[…]}, herds:[[kind,n]], layout(ctx){…}})`: `props` become `OBJ` entries, `sizes` feeds the size-matched scatter, `layout` fills one 80×80 chunk with the same `ctx` as `ZONE_LAYOUT`. NEW WORLD mixes in up to two themed zones; the first world stays the hand-made map. Test with `__sp.zone('<name>')`, which builds a patch of the zone next to the car.
- **Zone music + sounds (L22):** add `music:{drive:'candy_drive',boss:'candy_boss'}` and `sfx:{crash:'candy_crunch',boom:'candy_pop',land:'candy_squish',ambient:'candy_ambient'}` to `registerZone`. Music ids are tracks in `assets/sounds/music/`, sfx ids are clips in `assets/sounds/sfx/` (`candy_crunch_1`, `_2`… are random variants). The drive track cross-fades in when the camera has shown the zone for ~2.5 s; `music('boss')` plays the zone's boss track (or `music('boss',{zone:'candy'})`). Smashes, building crashes and blasts play the zone's `crash`/`boom` by where the object is; landings and falling props play `land`; `ambient` is a quiet loop while you're in the zone. One prop can override its crash sound with `sfx:'gummy_squish'` in `makeObj`/`sized` opts (or `o.sfx=…`). Anything missing falls back to the default sound.
- **Indoor zone (L20, the bedroom):** a zone with `indoor:{half:80,wallH:44,floor,wall}` is a whole world on its own: one room `2·half` square around the origin (no roads, home arena or edge walls), picked on the start screen (🛏️ / 🌳). Same `registerZone` fields as a themed zone (`props`, `sizes`, `layout(ctx)`, `sky`, `herds:[]`), plus optional `room(half)` returning a `THREE.Group` shell (floor top at y≈0, walls just outside ±half, low or open toward +Z where the camera is), `start:[[x,z],[x,z]]`, and `breakout:['bedroom_door',…]` (or `makeObj` opts `{breakout:true}`). Its size class decides when you can get out: once the players reach it, an arrow points at it and smashing it plays BREAK OUT! and rolls a fresh outdoor world at the same size. Layouts run per chunk as usual: `ctx.place` the furniture at fixed room spots and only the ones inside that chunk land. Logic's placeholder room and door (`BEDROOM_DEFAULT`, game.js) are used until `src/world/zones/bedroom.js` registers `id:'bedroom'`. Test: `__sp.room()` enters it, `__sp.room(false)` goes outside.
- **Smashable object:** add to `OBJ` using `makeObj(x,z,radius,height,points,build)`. In `build`, register parts with `P(mesh, chunks, whole, half)` — `whole:true` flies off intact, otherwise it shatters into `chunks` boxes. Add it to `SPAWN_W` to respawn. Give it a size class with opts `{size:'micro'|'mini'|'tiny'|'small'|'medium'|'large'|'huge'|'mega'}` (each size is ~1.65× the last; a `small` thing is about the size of a car at scale 0.2, a cone is `small`… see `TYPE_SIZE` in game.js: cone = small, house = huge). Players can only smash things at or below their size; bigger things get a red ring and boing them back; things 3+ sizes below get squished without counting. Any `OBJ` type can also be built shrunk or grown: `OBJ.cone(x,z,arg,scale)`.
- **Size-matched props:** define `const ZONE_PROPS={town:{mini:['flower',…],tiny:[…],small:[…],…},farm:{…},park:{…},home:{…}}` in `objects.js` (OBJ type names per zone per size). Logic keeps the area around the cars stocked from it: mostly the players' size, some a size or two bigger, a few smaller. Missing entries fall back to today's props shrunk or grown.
- **Building (staged destruction):** make it with `makeObj(x,z,r,h,points,build,{building:true,size:'huge'})` and tag every part with `BP(mesh, floor, kind)` (from `core.js`): `P(BP(mk(...), 0, 'wall'), 3)`.
  - `floor`: 0 = ground floor, counting up. Put the roof on the floor above the top storey (or tag it `'roof'` on the top floor).
  - `kind`: `'wall'` holds up everything above it. Build each storey from **several** wall pieces (about 8–12, e.g. 3 per side) so they can be knocked out one at a time. `'slab'` is a floor or ceiling plate, `'roof'` is the roof, and `'extra'` covers windows, doors, signs and chimneys (usually `whole:true` so they pop off intact).
  - Storey heights come from the parts themselves, so no numbers are needed. Keep it under ~60 parts.
  - What happens: when fewer than half (`SUPPORT`) of a storey's walls are left, everything above it drops, tilts and pancakes storey by storey, then the stump crumbles. Way-smaller cars boing off, smaller cars chip 1–2 pieces, same-size cars plow through and bigger cars flatten it. Barrel blasts blow out nearby parts. Knocked-out parts are remembered per chunk.
  - Working example: `demoBuilding()` in `game.js`. Try `__sp.building(x,z,floors)` in the console.
- **Voice line:** call `say('Exact Text!')` in code and add the same text to `tools/voice-lines.json` (car names are picked up automatically). Then on the machine with the ElevenLabs key in `.env`, run `node --env-file=.env tools/make-voices.mjs` (`--dry` first to see what it will make and the character cost). It only generates new or changed lines. Lines without a clip use the browser's robot voice, so nothing breaks while a line is waiting for a recording.
- **Music:** tracks live in `tools/music-lines.json` (`title`, `drive`, `boss`, `victory`), made with `node --env-file=.env tools/make-music.mjs` (`--only=boss` to redo one). Code switches tracks with `music('boss')` or `music('victory',{loop:false,then:'drive'})`.
- **Sound effect:** add `id: {prompt, dur}` to `tools/sfx-lines.json` (ids like `crash_1`, `crash_2` are random variants of `crash`; the built-in `sfx.*` sounds use clips with the same names when they exist), run `node --env-file=.env tools/make-sfx.mjs`, and play it with `sfxClip('id')` (it returns false if the clip isn't there, so keep a synth fallback).
- **Animal** (in `src/world/animals.js`)**:** fill `const ANIMAL={chicken:{build(){…return group},fluff:'#ffffff'},…}` to replace logic's placeholder looks (`ANIMAL_DEFAULT` in game.js). `build()` returns a `THREE.Group` facing +Z with its feet at y=0, real-ish size (chicken ~0.7 long, cow ~2.6); size class is worked out from its size. `fluff` is the puff color when launched. Kinds today: chick, chicken, duck, goose, bunny, cat, dog, pig, sheep, goat, cow, horse (each has a sound in `sfx-lines.json`; a new kind needs one too). Zone layouts place herds with `ctx.herd(kind,x,z,n)`; chunks without herds get a default mix from `ZONE_HERDS`.
- **Boss** (in `src/world/bosses.js`)**:** fill `const BOSSES=[{id,name,emoji,sway,build(P,g){…}},…]` to replace logic's placeholders (`BOSS_DEFAULT`: Clankzilla, Shelldozer, King Wobbles). A random one drops in each world once the players are GIANT. `build` works like a building: `P(BP(mesh,floor,kind),chunks,whole,half)` at 1x scale (about 11 tall, radius ~3.6; logic scales it ×`BOSS_SCALE`). Weak spots: `P(bossWeak(mesh,floor,phase),3)` with phase 1, 2, 3… (2 per phase works well), placed low (under ~3.5 at 1x) and on the outside. Themed bosses: set `zone:'candy'` (a registered zone id). At GIANT the boss comes from the zone the players are in, else from a themed zone elsewhere in the world, else a general (no `zone`) boss, never the same one twice in a row when there's a choice. It plays the zone's `music.boss` track and its landing dust uses the zone's `bossDust` (or `ground`) color. Optional `taunts:['…']` replace the generic hit lines and `defeat:'…'` is said before "You beat the boss!". Add `Here comes <Name>!`, the taunts and the defeat line to `tools/voice-lines.json`. In the bedroom (L29) the boss is scaled ×4 instead of ×7, guards the door, and beating it bursts the door open (BREAK OUT); set `zone:'bedroom'` for bedroom bosses. Test with `__sp.boss('id')` or `__sp.boss('zone:candy')`.

## Testing
- Serve locally (`python3 -m http.server`) — the game (ES module boot) and models only load over http, not `file://`. `?q=phone` / `?q=high` forces a quality (also in the pause menu).
- Headless SwiftShader can't render the new shadows reliably; for visual checks run Chromium on the real GPU (`--use-angle=metal --enable-gpu` on a Mac).
- `window.__sp.mega()`, `__sp.explode(x,z)`, `__sp.addScore(n)`, `__sp.grow(n)` (1800 = GIANT), `__sp.newWorld()`, `__sp.tp(x,z)` and `__sp.stats()` in the console help with testing. Press N (or START) when giant for a new world.
- Keyboard: P1 WASD/Space/E/Q/R, P2 Arrows/Enter/RShift///. Esc / START / ⏸ pauses (the pause menu also shows what each controller button reports). (drive/turbo/jump/level up/shoot; Q, /, R and . LEVEL UP when ready; ` cycles cars for testing). `__sp.level(n)` jumps ahead n sizes (`__sp.level(n,true)` skips the garage), `__sp.garage()` opens the garage for the current tier. Check both players, a ramp jump, a barrel chain, and a MEGA SMASH before pushing.
